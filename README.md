# Архив погоды — Go / Windows

Нативный GUI для Windows, без Python, браузера, CGO и внешних Go-зависимостей.
**API-ключ и регистрация не нужны.** Погода и поиск городов работают через Open-Meteo.

## Запуск

Нужен Go 1.27.1 или новее (версия текущего проекта).

```powershell
go run .
```

Сборка приложения без консольного окна:

```powershell
go build -ldflags="-H=windowsgui" -o build/CityWeather.exe .
Copy-Item cities.json build/cities.json
```

Или выполните `./build.ps1`: скрипт также создаст переносимый архив
`build/CityWeather-windows-amd64.zip` с exe и файлом городов.
Сборка предназначена для Windows x64. Иконка встроена в exe, окно и панель задач.

Исходник оригинальной иконки (солнце, облако и термометр) — `internal/icon/main.go`.
Готовые `assets/app.ico`, `assets/app.png` и `resources_windows_amd64.syso` находятся
в Git, поэтому обычной сборке не нужны дополнительные инструменты и интернет.
Для изменения иконки выполните `go generate .`: генерация ресурсов использует
закреплённую версию `github.com/akavel/rsrc@v0.10.2`, загружаемую Go автоматически.

Запустите `build/CityWeather.exe`. Для переноса достаточно exe и `cities.json`;
установка Go на другом компьютере не нужна. Файл городов ищется рядом с exe,
а при `go run .` — в рабочем каталоге. `.env` и переменные с ключами не используются.

## Работа с городами

Города хранятся отдельно в `cities.json`. Поиск по названию, региону и стране
фильтрует локальный список. Кнопка «Найти в интернете» ищет до 50 совпадений
через Open-Meteo / GeoNames. Результаты можно выбрать в списке; они действуют
до изменения поиска и не изменяют файл городов. Одноимённые города различаются
по региону и стране. Для уточнения можно ввести, например, `Paris, France`.
Интернет-поиск запускается кнопкой, а не при каждом вводе.

## Период и данные

По умолчанию запрашиваются **7 завершённых календарных дней**, до вчерашнего
дня включительно. Можно задать от 1 до 366 дней. Границы периода рассчитываются
по местному времени города. Часы получаются как Unix timestamps и переводятся
в часовой пояс города для каждой записи, с учётом переходов на летнее время.

Каждая строка — один день; две группы столбцов показывают температуру в °C,
влажность в % и погодные условия в **08:00** и **14:00** по времени города.
Это температура в выбранные часы, а не суточные минимум и максимум.
Пропущенный день, час или значение обозначается «нет данных». Во время загрузки
доступны отмена и закрытие окна. При ошибке прежняя таблица сохраняется;
её город и период указаны отдельной строкой.

Температура на 08:00 выделена голубым, на 14:00 — персиковым.
Двойной щелчок по температуре копирует одно число; также можно щёлкнуть по
нужной ячейке и нажать Ctrl+C. В буфер попадает, например, `-2.7`, без `°C`.
Кнопки «Копировать 08:00» и «Копировать 14:00» копируют весь соответствующий
столбец: по одному числу на строку, без заголовка. Пустые значения остаются
пустыми строками, чтобы при вставке сохранялось соответствие датам.

Источник: [Open-Meteo Historical Weather API](https://open-meteo.com/en/docs/historical-weather-api),
`https://archive-api.open-meteo.com/v1/archive`, модель **ECMWF IFS**.
Она предоставляет почасовые данные с 2017 года, включая последние дни.
Это модельная оценка прошлой погоды с пространственным разрешением около 9 км;
значения могут отличаться от измерений конкретной метеостанции.
Выбор этой модели явный: архив ERA5 имеет задержку около 5 дней и потому не
подходит для полного периода до вчера без дополнительного источника.
Если значение ещё не опубликовано провайдером, приложение показывает пропуск.

[Бесплатный публичный API](https://open-meteo.com/en/pricing) доступен без ключа
для **некоммерческого использования** с ограничениями частоты запросов.
Для коммерческого применения провайдер требует платную лицензию.
Длительные периоды учитываются сервисом как несколько вызовов; HTTP 429
отображается как ошибка лимита. Данные Open-Meteo распространяются по CC BY 4.0;
атрибуция Open-Meteo / ECMWF IFS указана в окне приложения.

Поиск городов: [Open-Meteo Geocoding API](https://open-meteo.com/en/docs/geocoding-api),
географические данные GeoNames.

## Файл городов

```json
[
  {
    "name": "Уфа",
    "lat": "54.7388",
    "lon": "55.9721",
    "timezone": "Asia/Yekaterinburg",
    "country": "Россия"
  }
]
```

Координаты принимаются числами или строками. `country`, `region`, `timezone`
необязательны. Если часовой пояс отсутствует, приложение получает его у
Open-Meteo дополнительным запросом с `timezone=auto`. Некорректные координаты,
неизвестный часовой пояс и пустой файл обнаруживаются при запуске.
После ручного изменения файла перезапустите приложение.

## Проверка

```powershell
go test ./...
go vet ./...
```

Обычные тесты работают с локальным HTTP-сервером. Они проверяют часы, пропуски,
переходы дат и летнего времени, ошибки API и отсутствие аутентификации в запросе.
Необязательная проверка реального сервиса (требует интернет):

```powershell
$env:CITYWEATHER_LIVE_TEST = '1'
go test -run TestLiveOpenMeteo -v
```
